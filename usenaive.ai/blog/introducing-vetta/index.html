Introducing Vetta: the most efficient harness for long-horizon tasks

Vetta is our agent harness for work measured in hours. With the model held fixed and only the wrapper changed, it costs $0.2232 per task against $0.5995 for the next-best harness — 2.7x cheaper, while completing more of them.

Vetta is our agent harness for long-horizon work — tasks measured in hours rather than seconds, where the agent keeps its own state, decides what to re-read, and finishes without a person in the loop. On a long-horizon terminal benchmark that holds the model fixed — zai-org/GLM-5.2-FP8 in every arm — and changes only the wrapper, Vetta spends $0.2232 per task against $0.5995 for the next-best harness at the same latency setting. That is 2.7x cheaper, while completing more of them: 12 of 16 against 11 of 16.

A harness is the wrapper around a language model: what the model sees each turn, which tools it can reach, what it is allowed to spend, and what happens between turns. The model is a commodity, and every arm in this study ran the same one. The harness is where the cost of a finished piece of work is actually decided.

How it is built

The base is the pi harness — the core agent loop and context management. Everything above it is ours.

The Vetta system prompt governs what goes in front of the model each turn and what is deliberately not re-sent. A tool connection layer gives the agent web search, a browser, a sandbox, storage and third-party connections through one surface. Sub-agent delegation extends the same idea about context that the prompt does: work splits into bounded task trees, so a child carries only the context its own sub-task needs rather than inheriting the whole history. Delegation is strictly sequential — it buys context isolation, not wall-clock.

Two layers decide the bill rather than the capability. The completion window picks a price for the deadline, and has its own section below. Budget enforcement prices every call before it is made and refuses it if it would breach the cap; an agent cannot be created without one. The protection is structural rather than a report you read the next morning, which is what makes it safe to leave an agent running unattended overnight.

Underneath all of it, durable state and scheduling. The loop is an alarm, not a call stack: an agent wakes, takes one turn, commits what it learned, and sleeps. A run that spans hours survives a crash, a restart and a machine change, and loses one turn rather than the whole run. Waiting costs storage rather than compute.

The layering is itself measurable, because the bare base loop is one of the arms. On the same model and the same tasks, pi alone costs $1.1016 per completed task and finishes 9 of 16. Vetta, on that identical base, costs $0.2976 and finishes 12.

What a finished task costs

Fifteen cells: five harnesses across three completion windows, one fixed model throughout, full 8-of-8 instance coverage, n=16 attempts per cell. Thirteen of those cells carry measured dollars. Vetta takes 1st and 2nd on cost per completed task and three of the top four places.

The row that matters commercially is the fourth one. immediate is the default, and it is the only like-for-like comparison in the table — the one where both sides answer at the same speed. There Vetta finishes a task for $0.2976 against $0.8720 for the next-best harness, having spent $0.2232 per attempt against $0.5995. It is not finishing fewer to get there: 12 of 16 against 11.

The two cheaper Vetta rows above it are real, and they are not the headline. They are what happens when you are willing to wait.

The completion window

The completion window is a single field on the request with three settings. immediate answers now. priority answers soon. loose answers eventually. The model is identical in all three; what changes is the tariff and the latency. On the wire they keep their internal names — asap, standard and flex.

Priority is the interesting setting. It completes 13 of 16 — the highest completion count of any cell in the study — at $0.2332 per completed task, which is 21.6% below Vetta's own default. It finishes more work and costs less. The only thing it spends is time.

That trade is the whole point. An agent a person is watching should be on immediate. An agent that starts at midnight and delivers at nine has no reason to be, and pays materially less for the same model. Being able to say which one a given task is, per request rather than per deployment, is the feature.

A cheap bill is not automatically a saving

The loose window produces the cheapest number in the study, and most of that number is not what it looks like.

Decompose each arm's loose bill against its own priority bill as total = rate × volume. The rate term — the tariff discount itself — lands between 0.69x and 0.80x for every arm measured, including ours. Everything below that is not a discount. It is the agent buying less work, because a looser window lets each call run longer inside the same wall-clock cap: roughly 80 seconds per call at loose against roughly 30 at immediate. Vetta's volume term is 0.718.

Bare pi is the control that proves the mechanism, and it is a clean one because it is cap-bound at both windows — it hits the clock on 69% of loose attempts and 75% of priority ones. It has no slack to give up. Its volume does not fall; it rises, to 1.271x. And its loose bill lands at 1.005x its own priority bill. Same rate discount, none of the apparent saving.

So a loose cell that looks cheap because its trials died early is not a cheaper result, and we do not present it as one. Every dollar in this post is per completed task, a metric that cannot be improved by completing fewer, and the headline rests on immediate, where both sides answer at the same speed.

What these numbers do not say

Dollars are measured, not modelled. Our own rate card bills every input token at the full input rate; the vendor bills cache-read input at a fifth of it. The size of that over-statement is a property of the harness and the window — measured, it ranges from 1.017x to 4.176x. Ranking harnesses on card dollars is therefore meaningless; it mis-ranks by up to four times. Every figure above is corrected against vendor invoice brackets. Two cells (bare pi at priority and loose) had their brackets refused by the quiescence gate, so they carry no dollar anywhere and are not ranked on cost.

The deflators are not exact. Twelve of the fifteen are a single invoice bracket over a single trial, applied cell-wide. The one cell measured twice differed 10.8% between days. Treat them as ±10%. Every ranking here survives that comfortably — the like-for-like lead is 2.7x — but they are not precise constants.

One cell is n=15. Harness B at loose excludes a single run whose agent binary never installed, which would have graded an untouched repository as a failure. Cost per completed task is unaffected; that denominator is completions.

Warning

Vetta is in early beta, and the build measured here is ahead of what ships today. The measured arm runs Vetta's prompt, tool surface and thinking budget on the pi agent core. The durable runtime — the alarm loop, the per-turn commit, the task board — is what the product deploys, and it is a different codebase that has not caught up. The measurements are real; the shipped harness is behind them.

The window is served on one model. On any other, a request for standard or flex is refused with a typed error — window_unavailable, HTTP 400 — rather than quietly downgraded. The failure that refusal exists to prevent is accept-and-drop: a caller asks for a discount, the edge serves the default, and the manifest, the meter row and the results table all agree on a price nobody was charged.

Warning

That refusal is not reachable on every surface yet. A QA pass against staging found two paths where a window is still accepted and dropped: a per-task window replaced by the agent's own, and a non-default window on an unsupported model billed rather than refused. The first fix is committed and the deployed edge worker is behind it. Nothing in this post runs through either path — every figure was produced with the window pinned per arm.

Frequently Asked Questions
What is Vetta?+
An agent harness for long-horizon work. It is built on the pi harness — our core agent loop and context management — with the Vetta system prompt, a tool connection layer, the completion window, sub-agent delegation, budget enforcement and durable scheduling layered on top.
What does 'most efficient' mean here?+
Lowest cost per task actually completed, with each harness charged for everything it burned on tasks it never finished. At the default latency setting Vetta is 2.7x cheaper per task than the next-best harness while completing more of them.
What is the completion window?+
Three service levels for one model, chosen per request: immediate, priority and loose. A looser window is priced lower per token and answers slower. On the wire they are asap, standard and flex.
Are the dollar figures list price or actual cost?+
Actual cost — what the vendor billed. Our own rate card books all input at the full input rate and over-states real cost by between 1.017x and 4.176x depending on the harness and the window, so ranking on list price is meaningless.
Is the cheapest number in the study the headline?+
No. The cheapest cell is Vetta at the loose window, but that is not a same-latency comparison and part of its saving is the agent doing less work inside the same cap. The headline rests on the immediate window, where both sides answer at the same speed.
